# AR-044 — Research experiment manifests

Generate a reproducibility manifest alongside an **executed AR-039 fictional benchmark** report:

```bash
python -m scripts.experiment_manifest create results.json \
  --experiment-id study-001 --model-version v1 \
  --dataset-version synthetic-adversarial-v1 --prompt-version llm-judge-v1 \
  --output manifest.json
python -m scripts.experiment_manifest verify manifest.json results.json
```

The manifest captures operator-declared experiment ID, model identifier and version, dataset version, prompt version, UTC-offset timestamp, optional notes, fixture count and SHA-256 hash of the canonical benchmark report. The verify command checks that the report still matches the stored checksum and declared model.

Manifests do **not** capture API credentials, automatically identify a provider's deployed weights, or prove model reproducibility: a provider can change a model behind the same identifier. Dataset/prompt version strings are operator-declared and not independently attested. A future version should hash prompt templates and fixture snapshots and record runtime parameters before claiming end-to-end reproducibility. Never put secrets or patient information in notes.

The CLI refuses to overwrite existing manifest files. No network calls, API routes or external model execution are introduced. Test: `python -m unittest discover -s tests -v`.
