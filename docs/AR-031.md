# AR-031 — Audit integrity hardening

Adds cooperative POSIX advisory file locking for audit writers and independently stored checkpoint files containing a sequence number and chain-head SHA-256. The checkpoint verifier rejects truncation and historical rewriting before the anchored head. Checkpoints use exclusive creation and cannot be overwritten by the CLI.

```bash
python -m scripts.audit_integrity --path local/research-audit.jsonl append --event-type manifest_registered --release-id research_001 --artifact-sha256 <64-character-digest>
python -m scripts.audit_integrity --path local/research-audit.jsonl checkpoint --output local/anchors/anchor-001.json
python -m scripts.audit_integrity --path local/research-audit.jsonl verify --checkpoint local/anchors/anchor-001.json
```

To require an existing checkpoint before appending, pass `--checkpoint local/anchors/anchor-001.json` to the `append` command. Checkpoint files should be copied to independent, access-controlled storage. They are checksummed but **not signed**; an administrator who controls both files can rewrite them. Advisory locks coordinate only writers that use this API, and `fcntl` requires POSIX systems. The older unguarded AR-030 CLI remains available for backwards compatibility; use the hardened CLI for new writes. No deployment or clinical approval is performed.
