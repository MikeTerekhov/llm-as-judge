# AR-015 — Operator-only synthetic model execution

This milestone adds a CLI to compare an explicitly configured model against **six hardcoded synthetic benchmark examples**. It does not accept arbitrary prompts, patient records, or browser inputs. The existing API and dashboard remain offline by default.

## Operator setup

Set the following environment variables locally (never commit actual credentials):

- `AI_REGIMEN_ENABLE_MODEL_JUDGE=true`
- `AI_REGIMEN_MODEL_ENDPOINT=https://your-approved-host.example/v1/chat/completions`
- `AI_REGIMEN_MODEL_ALLOWED_HOST=your-approved-host.example`
- `AI_REGIMEN_MODEL_NAME=your-approved-model`
- `AI_REGIMEN_MODEL_API_KEY=your-secret`

Run `python -m scripts.run_model_comparison` from the repository root. The command emits aggregate outcomes and synthetic example IDs, not prompts, evidence text or secrets. Without exact opt-in it refuses to run.

## Safeguards and limitations

The runner checks HTTPS, port 443 and an explicitly allowlisted hostname. Transport requests have a timeout and response-size cap, and model output is schema-validated and fail-closed. No external model was called during development.

**Not a production security boundary:** hostname allowlisting does not prevent DNS rebinding, internal-address resolution, proxy routing, or redirects. The HTTP transport explicitly rejects redirects. Use a trusted, fixed provider endpoint with appropriate network egress controls, credential scoping, and vendor privacy review. Do not deploy the CLI as an untrusted public service. The application cannot automatically detect PHI. Model judgments never approve clinical claims.

Run tests with `python -m unittest discover -s tests -v`.
