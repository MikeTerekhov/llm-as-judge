# AR-006 — CI and manual evidence review gate

## Automated checks
GitHub Actions runs Python unittest discovery and a Next.js production build on pushes and pull requests. The workflow uses npm install because the frontend does not yet have a committed lockfile. Add and commit a lockfile, then switch to npm ci for reproducibility.

## Review gate
`clinical.evidence_review.load_approved_index(snapshot_path, review_path)` loads only evidence snapshots with a matching SHA-256 digest and explicit source/table review flags. A review JSON file contains an array of:
```json
{
  "document_id": "SYN-1",
  "sha256_digest": "<snapshot SHA-256>",
  "reviewer": "research-reviewer",
  "reviewed_at": "2026-11-18T13:00:00Z",
  "source_checked": true,
  "tables_checked": true,
  "notes": "Source, tables, footnotes and date manually inspected"
}
```
This is a self-attestation, not an authenticated electronic signature or proof of medical validity. Review files must not contain PHI.

## Remaining limitations
The AR-005 HTML extractor still flattens source tables and may omit clinical context. Do not approve clinical source snapshots until table and footnote fidelity has been independently checked. The API still intentionally uses an empty evidence index. This milestone does not connect evidence to clinical decisions, implement authentication, or support patient data.
