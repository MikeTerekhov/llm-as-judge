# AR-025 — Synthetic evaluation regression tracking

This milestone compares AR-023 JSON reports with validated report checksums. It blocks unexpected changes to fixture fingerprints, lexical screening outcomes, or hand-authored fixture labels. Changes to human review counts and quality-gate status are surfaced separately; these do not imply an evaluator regression. Schema mismatches and invalid checksums are rejected.

Run:

```bash
python -m scripts.compare_evaluation_reports --baseline baseline.json --current current.json --output artifacts/evaluation-regression.json
```

`--allow-fixture-changes` permits deliberate fixture revisions but never silently permits changed evaluator/label outcomes. Review changes carefully before accepting a new baseline. The GitHub Actions pull-request regression job checks out the PR base commit and head commit into separate directories, generates an offline report at each revision, compares them, and uploads the comparison JSON even if regression checks fail.

No LLM is invoked. CI contains no human reviews. A report checksum is an integrity check, not an authenticity guarantee. These checks detect changes, not clinical accuracy or correctness.
