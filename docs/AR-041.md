# AR-041 — Visual model comparison dashboard

Open `/judge/model-comparison` in the Next.js frontend. Select between 2 and 8 JSON files generated by the explicitly opt-in AR-039 runner. Each report must be an executed twelve-fixture benchmark, at most 1 MiB. The browser parses the files locally and does **not** upload them or call the API.

The dashboard validates distinct fixture identifiers, expected labels, and model verdicts. All uploaded reports must contain matching fixture identifiers and authored labels. It shows per-run returned verdict coverage, conditional agreement with authored labels, macro F1, pairwise disagreements and shared-subset agreement. A selector allows inspection of cases where two runs returned different verdicts.

No external model is invoked by the dashboard. Model identifiers are taken from user-provided files and are not verified. Rates are descriptive, based on a small fictional authored dataset, not clinical accuracy or model superiority. No patient data should be uploaded or used.

Verify with `cd frontend && npm run build` and `python -m unittest discover -s tests -v`.
