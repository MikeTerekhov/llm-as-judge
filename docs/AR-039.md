# AR-039 — Expanded adversarial benchmark

The core set of 12 hand-written adversarial examples is too small to measure an evaluator. `clinical/adversarial_expanded.py` adds **360 generated fictional examples**: 36 templates, each applied to 10 fictional scenarios. The core 12 are unchanged, and the API, dashboards and human-review tooling still use them.

## Design

- **Every label comes from a rule.** Each template applies one change (a negation, a different count, a hedge and so on), and every example it produces gets the same label. That makes labels consistent and auditable, but they are not independently human-verified.
- **Open and explicit differences are paired.** Evidence that gives a *different* detail ("Module D passed") is labelled `insufficient_evidence`, matching the core set. Evidence that *rules out* the claim ("Only module D passed") is labelled `contradicted`. This pairing exists for scope, time and entity, so the benchmark measures whether an evaluator can tell the two apart.
- **A held-out test split.** Scenarios 1–7 are `dev` (252 examples) and scenarios 8–10 are `test` (108). Splitting by scenario means no object or wording appears in both. Tune thresholds or prompts on `dev` only.
- **New categories.** Besides the core seven (negation, quantity, uncertainty, scope, time, entity, causality), the set adds `conditional`, `paraphrase` (active vs passive voice, where word matching raises false alarms) and `distractor` (a similar sentence about another object sits next to the relevant one).
- **Reporting.** `benchmark_semantic` now reports 95% Wilson confidence intervals, a false-support rate (unsupported claims called supported, out of all unsupported claims), and results per split and per template, with word-matching errors alongside for comparison.

```bash
python -m scripts.run_semantic_benchmark --dataset expanded --split dev
```

## Result: `cross-encoder/nli-deberta-v3-base` @ `6c749ce`

Default thresholds (0.9), all 360 examples:

| Metric | Result |
| --- | --- |
| Agreement with labels | 80.6% (95% CI 76.2–84.3%); dev 79.8%, test 82.4% |
| False-support rate (NLI) | 4.7% (9 of 190 unsupported; CI 2.5–8.8%) |
| Unsupported claims passed by word matching | 70 of 190 |
| Unsupported claims passed by both screens, so sent to human review as if supported | **9** |

Findings:

1. **Conditionals are a real safety gap.** In 9 of 10 cases, the model treated "If the main switch is on, the blue beacon is active" as support for "The blue beacon is active" (entailment ≥ 0.96). Word matching passes these too, so they reach human review looking supported. All 9 false supports are this template. Fix this before relying on the NLI check, for example with a structural check that flags conditional evidence.
2. **The model does not tell open from explicit differences.** It called both "Module D passed" and "Only module D passed" a contradiction of "Module C passed". The same held for days and for "may" vs "always". These cases are still flagged, so this costs label agreement, not safety. If the project prefers "different detail means contradicted", relabel the `-open` templates; the pairing makes that a one-line change per template.
3. **"Contradiction wins" causes false alarms with distractors.** In 3 of 10 cases, "The red beacon is not active" was scored as contradicting "The blue beacon is active", which outweighed the correct supporting sentence beside it. This is conservative, but limiting the contradiction check to sentences about the same object would recover these.
4. **Weak on bounds and quantifiers.** It missed "more than five" vs "exactly five" (9 of 10 called insufficient), and "all passed" never counted as support for "some passed" (0 of 10). These are flagged, not passed.
5. **Strong where word matching fails.** It scored 100% on negation and paraphrase, and 95% on causality. Word matching passed all 20 negation cases and 10 distractor cases that it should have flagged.

While building the set, one scenario pair ("the relay unit" and "the backup relay") turned out to be ambiguous: the model reasonably read them as the same object. It was renamed to "relay unit seven" and "relay unit nine". The result above is after that fix.

## Limitations

Template-generated sentences are short and uniform; real guideline text is longer and messier. Ten scenarios per template measure consistency more than generality. Labels follow stated conventions that a reviewer could reasonably dispute. None of this measures clinical correctness.
